## Idle connections

| Measurement | Result |
|---|---|
| Connections held | 3,000 for 15 s, 3,000/3,000 still working afterwards |
| Balancer memory (RSS) | 4.1 MiB idle, 57.6 MiB while holding (about 18 KiB per connection) |
| Balancer open files | 7 idle, 18,007 while holding (6 per connection) |

On Linux, `io.Copy` between two TCP sockets uses `splice`, which needs a pipe pair per direction. That is where the extra 4 file descriptors per connection come from, and also why memory per connection stays low.

## Experiments (not merged)

These were run on the same machine with an earlier version of the same harness, to size two planned changes.

**1. Upstream pool removed.** Every session dials its own upstream connection. Change in `proxy/tcp.go`:

```diff
-	backendConn, err := p.pool.Get(backendAdd)
+	backendConn, err := net.DialTimeout("tcp", backendAdd, 5*time.Second)
 ...
-	backendConn.SetDeadline(time.Time{})
-	p.pool.Put(backendAdd, backendConn)
+	backendConn.Close()
```

| Concurrency | v0.1 p50 / p99 | Pool removed p50 / p99 |
|---|---|---|
| 1 | 50.8 / 52.5 ms | 0.3 / 0.9 ms |
| 10 | 51.3 / 54.0 ms | 2.0 / 5.3 ms |
| 100 | 54 to 56 / 65 to 78 ms | 18 to 19 / 36 to 48 ms |

At concurrency 100, throughput went from about 1.8k to about 5.2k sessions/s.

**2. Hash finalizer.** The FNV-1a output is passed through murmur3's `fmix32`, with 500 virtual nodes per backend.

| Backends | v0.1 CV | With finalizer CV | v0.1 busiest / quietest | With finalizer busiest / quietest |
|---|---|---|---|---|
| 3 | 29.2% | 4.4% | 2.15x | 1.11x |
| 5 | 42.5% | 4.0% | 3.03x | 1.11x |
| 10 | 33.7% | 5.1% | 2.63x | 1.17x |
